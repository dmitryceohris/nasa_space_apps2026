Что уже есть в `main` (другими коммитами):
- Дедупликация задач: одна задача на ключ результата, повторный запрос получает тот же `job_id` (`api/jobs.py:63-82`; на живом контейнере проверено в ревью #9).
- Ограничение очереди: `MAX_PENDING_JOBS`, при переполнении 503 `busy` с `Retry-After: 5` (`api/jobs.py:76-77`, `api/main.py:48`). Кроме того, ограничение запросов на клиента: 429 `rate_limited` с `Retry-After` (`api/limits.py`, `api/main.py:35-38`).
- Атомарная запись: `result.json` через временный файл и `replace`, пишется последним (`api/cache.py:41-47`). Вырезки и списки экспозиций тоже пишутся атомарно (`api/irsa.py:146-157`), lookup-файл резолва тоже (`api/resolve.py:160-162`). Отдельные TTL для пустых и частичных результатов (`EMPTY_CACHE_TTL`, `PARTIAL_CACHE_TTL`, `api/cache.py:36-37`).
- Повторы к IRSA: 3 попытки, паузы 5 и 10 с, затем 502 `upstream`, а для задачи `{"status":"error"}` вместо зависания (`api/irsa.py:28-47`).

Что не вошло:
- Stale-кэш при недоступном архиве (просроченный результат с `stale: true` и предупреждением). Сейчас при недоступном IRSA ответ `{"status":"error"}`, и следующий запрос начинает новую задачу.
- 429 `queue_full` с настраиваемым `JOB_RETRY_AFTER` для переполненной очереди задач. В `main` этот случай отдаёт 503 `busy` с фиксированным `Retry-After: 5`.
- Настройка повторов через окружение (`IRSA_RETRIES`, `IRSA_BACKOFF`, `IRSA_TIMEOUT`, `IRSA_BASE_URL`). Без `IRSA_BASE_URL` недоступный архив нельзя воспроизвести локально без сети.
- Повторы для Sesame (`SESAME_*`). В `main` перебираются зеркала без пауз (`api/resolve.py:31,44`).
- Дедупликация параллельных резолвов SIMBAD и параллельных загрузок одной вырезки (per-key lock). В `main` дедупликация есть только на уровне задачи.
- Атомарная запись PNG. В `main` PNG пишутся напрямую, но `result.json` пишется последним.
