## Замечания

### 1. [P1] Stale-ответ обходит проверку версии схемы

Место: [`workdir/api/cache.py:46–51`](https://github.com/dmitryceohris/nasa_space_apps2026/blob/be2548ba1c2d6abece747d28dc07ebe423384044/api/cache.py#L46-L51), вызов — `api/jobs.py:104–114,136–142`.

`read(..., allow_stale=True)` возвращает результат **до** проверки `v != VERSION`. При отказе IRSA `_run` поэтому публикует `status: ready` из кэша любой старой версии, хотя обычное чтение его отвергает. У такого результата могут отсутствовать актуальные поля и сохраняться исправленная позже семантика измерений. `stale: true` сообщает о возрасте, но не делает схему совместимой. Штатный тест ветки сам закрепляет возврат кэша `v=1`.

Воспроизведено без сети: файл с `v=1`, текущая версия `5`; обычный `read` → `None`, затем runner с `ApiError(502, ...)` → `_poll` возвращает HTTP 200, `status: ready`, `stale: true` и старые кадры.

Если переносить stale-функцию, сначала проверять тип и **текущую версию** результата, затем разрешать обход только срока годности. Не возвращать результаты с несовместимой схемой. Переносить отдельным PR поверх итоговой интеграционной версии.

### 2. [P2] Завершённые задачи не удаляются, пока снова не запросят тот же ключ

Место: [`workdir/api/jobs.py:79–83`](https://github.com/dmitryceohris/nasa_space_apps2026/blob/be2548ba1c2d6abece747d28dc07ebe423384044/api/jobs.py#L79-L83), запись результатов — строки 125–148.

Истечение `JOB_HOLD_SEC` проверяется только у запрашиваемого `k`. Ошибки, частичные и stale-результаты по другим ключам остаются в `JOBS` без общего удаления. Лимит `_active_jobs` их не учитывает, поэтому серия уникальных запросов с отказом архива накапливает записи, а частичные ответы — ещё и полные структуры результатов. Короткий hold фактически не ограничивает срок хранения в памяти.

Воспроизведено: добавлены 25 ошибок с истёкшим час назад `hold_until`, затем опрошен новый ключ. Все 25 ошибок остались; всего 26 записей при одном активном задании. На main уже есть общий проход удаления завершённых записей по `JOB_RETENTION_SECONDS`.

Если переносить удержание результата для параллельных поллеров, сохранить общую очистку и ограничение числа/объёма сохранённых ответов. Аналогично проверить пожизненные словари `_inflight` в `irsa.py` и `resolve.py`.

### 3. [P2] При переносе старого обработчика вернётся раскрытие внутренних ошибок

Место: [`workdir/api/jobs.py:145–148`](https://github.com/dmitryceohris/nasa_space_apps2026/blob/be2548ba1c2d6abece747d28dc07ebe423384044/api/jobs.py#L145-L148); аналогично `api/main.py:44–47`.

Текст произвольного исключения попадает в публичное `message` или HTTP 500. Воспроизведено на искусственном `RuntimeError('private path /private/service/config-key.json')`: polling отдаёт этот путь клиенту. Реальных секретов в проверке не использовалось. Это унаследованное состояние старой основы, уже исправленное в актуальном main через общее публичное сообщение.

При разрешении конфликтов обязательно сохранить защиту из main: подробности — в журнале, клиенту — общее сообщение. Также сохранить `api/limits.py`, сроки задач, ключи с моделью движения и источником выборки, `allow_nan=False`, актуальные поля ответов и версию кэша. Замена конфликтующих файлов целиком версией workdir небезопасна.
