# API — требования (ответственный: Асанали)

## 0. Задача в одном абзаце
Бэкенд на **FastAPI**, который по координатам (или имени объекта) отдаёт фронтенду
**массив кадров SPHEREx по эпохам** (PNG + метаданные), спектр и кривую блеска.
Данные берутся вживую из NASA/IPAC IRSA через уже готовый модуль `src/Exposure`.
Обработку картинок (coadd / diff / trail / центроид) пишет Нурислам — API её только вызывает.

**Готово, когда:** все 5 тестовых объектов челленджа открываются по ссылке вида
`https://<host>/?target=WISE0855&fov=5&det=6&mode=diff` и показывают «видео».

---

## 1. Факты, которые определяют архитектуру (измерено на реальных данных)
| Факт | Следствие для API |
|---|---|
| Одна вырезка IRSA ≈ **4 МБ** и ≈ **13 с** | Синхронно ждать нельзя → **фоновые задачи + опрос прогресса** |
| На одну точку ≈ **60 снимков на детектор** (Барнард, авг 2025 – сен 2026) | Ограничить число скачиваемых снимков (см. `max_per_epoch`) |
| IRSA иногда отвечает **503** на первый запрос | Повторы уже встроены в `load_exposure`; API должен переживать пропуск кадра |
| Яркие звёзды насыщены (флаги `OVERFLOW`, `BLOOM`) | Отдавать маску флагов отдельной картинкой |
| Новые релизы SPHEREx выходят постоянно | Не хранить «базу», только кэш по ключу запроса |

---

## 2. Единые имена параметров (одинаковые в URL страницы и в API)
| Параметр | Тип | Диапазон / значения | По умолчанию | Пример |
|---|---|---|---|---|
| `target` | str | имя объекта (SIMBAD) | — | `Barnard's Star`, `WISE 0855-0714` |
| `ra` | str/float | градусы `0..360` или `08h55m10.83s` | — | `133.795` |
| `dec` | str/float | градусы `-90..90` или `-07d14m42.5s` | — | `-7.245` |
| `fov` | float | угл. минуты, `1..20` | `5` | `5` |
| `det` | int | `1..6` | `3` | `6` |
| `mode` | enum | `single`, `coadd`, `diff`, `trail` | `coadd` | `diff` |
| `max_per_epoch` | int | `1..20` | `6` | `6` |

Правила:
- Нужно **либо** `target`, **либо** пара `ra`+`dec`. Если есть оба — приоритет у `ra`/`dec`.
- Координаты парсить через `SkyCoord(ra, dec, unit=(u.deg, u.deg))`, а если строка содержит `h`/`:` — через `SkyCoord(ra, dec)` (sexagesimal).
- `fov` ограничен 20′: больше — слишком долгая загрузка.

## 3. Эндпоинты

### 3.1 `GET /api/health`
`200 {"status":"ok","version":"0.1.0"}` — для проверки деплоя.

### 3.2 `GET /api/targets`
Список пресетов для кнопок на фронте (захардкодить):
```json
[{"id":"barnard","name":"Barnard's Star","det":3,"fov":3,"note":"самое быстрое собственное движение, ~10.4″/год"},
 {"id":"epsindib","name":"eps Ind B","det":3,"fov":5,"note":"пара коричневых карликов, ищите метан"},
 {"id":"wise0855","name":"WISE 0855-0714","det":6,"fov":3,"note":"виден только на 4–5 мкм"},
 {"id":"rwaur","name":"RW Aur","det":2,"fov":3,"note":"переменная звезда T Tauri"},
 {"id":"rdra","name":"R Dra","det":2,"fov":3,"note":"мирида, период ~245 дней"}]
```
`id` можно передавать как `target=wise0855`.

### 3.3 `GET /api/resolve?target=...`
Имя → координаты и собственное движение (`astroquery.simbad`, поля `ra`, `dec`, `pmra`, `pmdec`, `plx_value`).
```json
{"name":"Barnard's Star","ra":269.452,"dec":4.693,"pmra_masyr":-801.6,"pmdec_masyr":10362.5,
 "parallax_mas":546.98,"ref_epoch":2000.0,"source":"SIMBAD"}
```
- `404` если имя не найдено.
- Кэшировать навсегда (в памяти + json на диске).
- ⚠️ `ref_epoch` обязателен: координаты SIMBAD даны на J2000, Барнард с тех пор ушёл на ~4.5′.
  Центр поля для запроса в IRSA = положение, **пересчитанное на сегодня** (`apply_space_motion`).
- Для 5 пресетов параметры уже есть в [`OBJECT_PARAMETERS.csv`](../OBJECT_PARAMETERS.csv) (Gaia DR3 и др., с погрешностями) —
  брать оттуда, а SIMBAD только для произвольных имён. Пересчёт на дату уже реализован в
  [`barnard_motion.py`](../barnard_motion.py) (пока только для Барнарда — обобщить на все цели).

### 3.4 `GET /api/view?...` — главный эндпоинт
Параметры — из раздела 2. Работает как **«получить или запустить»**:

1. Ключ кэша = `sha1(round(ra,5), round(dec,5), fov, det, mode, max_per_epoch)`.
2. Если результат в кэше → `200` + полный JSON (ниже).
3. Если задача уже идёт → `202` + прогресс.
4. Иначе запустить фоновую задачу → `202` + прогресс.

Фронт опрашивает тот же URL каждые 2 с, пока не придёт `200`.

**`202 Accepted`:**
```json
{"status":"running","job_id":"3f9a…","stage":"download","done":17,"total":42,"message":"Скачано 17 из 42 снимков"}
```
`stage` ∈ `query` → `download` → `process` → `render`.

**`200 OK`:**
```json
{
  "status":"ready",
  "query":{"ra":269.4463,"dec":4.768,"fov":3,"det":3,"mode":"coadd","target":"Barnard's Star"},
  "grid":{"width_px":30,"height_px":30,"pixel_scale_arcsec":6.15,
          "wcs":{"CTYPE1":"RA---TAN","CTYPE2":"DEC--TAN","CRVAL1":269.4463,"CRVAL2":4.768,
                 "CRPIX1":15.5,"CRPIX2":15.5,"CDELT1":-0.001708,"CDELT2":0.001708}},
  "frames":[
    {"index":0,"label":"Эпоха 1","mjd":60902.87,"date":"2025-08-15","det":3,
     "wave_um":2.07,"n_exp":6,
     "image_url":"/cache/3f9a/f0.png","flags_url":"/cache/3f9a/f0_flags.png",
     "predicted_px":[15.2,14.1],"measured_px":[15.4,14.0],
     "obs_ids":["2025W33_2C_0321_1", "…"]}
  ],
  "trail_url":"/cache/3f9a/trail.png",
  "motion":{"pm_measured_arcsec_yr":[-0.9,10.1],"pm_err_arcsec_yr":[1.2,1.2],"pm_reference_arcsec_yr":[-0.80,10.36]},
  "warnings":["Разница λ между эпохами 7% — остатки в diff могут быть не движением"],
  "credits":"NASA SPHEREx via NASA/IPAC IRSA"
}
```
Правила:
- `frames` отсортированы по `mjd`.
- `measured_px`, `motion` могут быть `null` (если центроид не прошёл проверки качества).
- Все пиксельные координаты в ответе (`predicted_px`, `measured_px`) — **в системе PNG**: 0-based, `[x, y]`, ось y **вниз**.
  ⚠️ В FITS/numpy ось y направлена **вверх** (север сверху получается только после переворота).
  **Решение:** при сохранении PNG делать `np.flipud(img)` и пересчитывать `y_png = height - 1 - y_fits`.
  Обе операции — в одной функции `render.py`, иначе маркеры уедут с объектов.
- `grid.wcs` — минимальный TAN-заголовок, чтобы фронт/Aladin могли перевести клик в RA/Dec.
- Ошибки задачи: `200 {"status":"error","message":"..."}` + задача удаляется из кэша, чтобы можно было повторить.
- Если снимков нет: `200 {"status":"ready","frames":[],"warnings":["SPHEREx ещё не наблюдал эту область"]}`.

### 3.5 `GET /api/spectrum?ra&dec[&target]`
Фотометрия в точке на всех экспозициях всех 6 детекторов (функция Нурислама).
Тот же механизм 202/200. Ответ:
```json
{"status":"ready","points":[
  {"wave_um":4.93,"bw_um":0.037,"flux_ujy":1520.0,"err_ujy":35.0,"mjd":60902.87,"det":6,"flags":["SOURCE"]}
],"n_rejected":12}
```

### 3.6 `GET /api/lightcurve?ra&dec&wave_min&wave_max`
Поток по времени в узком окне λ (по умолчанию окно = ±5% вокруг середины детектора `det`).
```json
{"status":"ready","wave_window_um":[2.0,2.3],"points":[{"mjd":60902.87,"flux_ujy":980.0,"err_ujy":20.0}]}
```

### 3.7 `GET /api/export.gif?<те же параметры, что /api/view>`
Анимированный GIF из готовых кадров (`imageio`). Только из кэша; если результата нет → `409`.
**Приоритет низкий.**

### 3.8 Статика
- `/cache/...` — PNG из папки кэша (`StaticFiles`).
- `/` — фронтенд (сборка Инжу/Зайнап), тоже `StaticFiles(html=True)`.

## 4. Формат ошибок (все эндпоинты)
```json
{"error":{"code":"bad_param","message":"dec должен быть в диапазоне -90..90"}}
```
| HTTP | code | Когда |
|---|---|---|
| 400 | `bad_param` | неверный/отсутствующий параметр |
| 404 | `not_found` | имя не найдено в SIMBAD |
| 409 | `not_ready` | экспорт до готовности результата |
| 502 | `upstream` | IRSA/SIMBAD недоступны (после повторов) |
| 500 | `internal` | всё остальное (с логом трейсбека) |

## 5. Как вызывать модули команды
```python
from Exposure import query_spherex, fetch_exposures, cutout_url, load_exposure   # готово
from processing.pipeline import run                                              # Нурислам

# Договор с Нурисламом (сигнатура фиксируется сейчас, реализация — позже):
# run(exposures: list[Exposure], center: SkyCoord, fov_arcmin: float, mode: str,
#     target_motion: dict | None, progress: Callable[[str, int, int], None]) -> PipelineResult
# PipelineResult: frames: list[Frame], trail: np.ndarray | None, motion: dict | None, warnings: list[str]
```
**Пока `processing` не готов** — сделать заглушку `run()`, которая для каждой эпохи берёт первую
экспозицию, вычитает `zodi`, режет до `fov` и отдаёт как кадр. Это уже рабочий режим `single`,
и фронт может начинать работать с реальными картинками с первых часов.

**Как ограничить загрузку (`max_per_epoch`):**
1. `query_spherex(center, detector=det)` → таблица (быстро, ~8 с).
2. Сгруппировать строки по эпохам (разрыв по `mjd` > 30 дней).
3. В каждой эпохе оставить `max_per_epoch` строк — равномерно по времени.
4. Только их передать на скачивание. Прогресс = скачано / всего.

## 6. Нефункциональные требования
- **Кэш:** папка `cache/` (путь из env `CACHE_DIR`). FITS кэширует astropy сам; результаты API — `cache/<key>/result.json` + PNG. Перезапуск сервера не должен терять кэш.
- **Прогрев:** при старте фоновая задача прогревает кэш для 5 пресетов с параметрами по умолчанию. **На демо ничего не должно качаться вживую.**
- **Время ответа:** из кэша < 1 с; холодный запрос ≤ ~3 мин с видимым прогрессом.
- **Параллелизм:** не больше 6 одновременных загрузок с IRSA на весь сервер (общий семафор), одна задача на один ключ.
- **CORS:** разрешить все origin (виджет должен встраиваться в чужие сайты).
- **Логи:** каждый запрос в IRSA (url, время, код ответа) — пригодится для отладки на демо.
- **Без секретов:** API ключей не нужно, IRSA и SIMBAD публичные.
- **Зависимости:** через `uv` (`pyproject.toml` + `uv.lock`), добавлять `uv add fastapi uvicorn`; запуск одной командой `uv run uvicorn api.main:app --port 8000`.
- **Деплой:** Render / Railway / HF Spaces (Docker). Нужен публичный URL для формы подачи.

## 7. Структура
```
api/
  main.py        # FastAPI app, роуты, CORS, static
  jobs.py        # фоновые задачи: dict[key] -> JobState, ThreadPoolExecutor, семафор IRSA
  params.py      # парсинг и валидация параметров (раздел 2) — pydantic
  resolve.py     # SIMBAD + пресеты
  render.py      # numpy -> PNG (flipud!), маска флагов -> PNG, GIF
  cache.py       # ключи, чтение/запись result.json
tests/test_api.py  # TestClient: health, bad_param, resolve, view на заглушке
```

## 8. Критерии приёмки (чек-лист для демо)
- [ ] `/api/health` отвечает на публичном URL
- [ ] `/api/view?target=barnard` → `202` с прогрессом → `200` с ≥3 кадрами
- [ ] Повторный запрос того же URL < 1 с
- [ ] Все 5 пресетов прогреты и открываются
- [ ] `dec=100` → `400 bad_param`; `target=asdfgh` → `404`
- [ ] Маркер `predicted_px` на PNG стоит на звезде (проверка переворота оси y)
- [ ] Ссылка `/?target=wise0855&det=6&mode=diff` открывает нужный вид сразу
- [ ] Отключённый интернет на сервере → кэшированные пресеты всё равно работают
