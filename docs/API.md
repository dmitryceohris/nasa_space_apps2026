# SPHEREx blink: API

Бэкенд на FastAPI. По координатам или имени объекта отдаёт массив кадров SPHEREx по эпохам (PNG и метаданные).
Данные берутся вживую из NASA/IPAC IRSA, имена и собственные движения из SIMBAD (через CDS Sesame).

- Базовый адрес (локально): `http://127.0.0.1:8000`
- Установка: `uv venv --python 3.12 .venv` и `uv pip install --python .venv/bin/python -r requirements.txt`.
  Зависимости API не входят в `pyproject.toml`; повторный `uv sync` удалит их из окружения, тогда поставьте заново.
- Запуск: `bash start.sh` (или `.venv/bin/uvicorn api.main:app --port 8000` из корня проекта)
- Тесты (без сети): `.venv/bin/python -m pytest -q tests/test_api.py tests/test_centroid.py`
- CORS открыт для всех origin.
- Все примеры ниже сняты с реально работающего сервера, полные версии лежат в `mock/`.
  Примеры ошибок `upstream` и `internal` составлены по тексту из кода, их на живом сервере не воспроизводили.

## Общие параметры

Одинаковы в URL страницы и в API (`/api/view`, `/api/export.gif`).

| Параметр | Тип | Диапазон / значения | По умолчанию | Пример |
|---|---|---|---|---|
| `target` | str | имя объекта (SIMBAD) или `id` пресета | нет | `Barnard's Star`, `barnard` |
| `ra` | str / float | градусы `0..360` или `08h55m10.83s`, `08:55:10.83` | нет | `133.795` |
| `dec` | str / float | градусы `-90..90` или `-07d14m42.5s` | нет | `-7.245` |
| `fov` | float | угловые минуты, `1..20` | `5` | `3` |
| `det` | int | `1..6` | `3` | `6` |
| `mode` | enum | `single`, `coadd`, `diff`, `trail` | `coadd` | `diff` |
| `max_per_epoch` | int | `1..20` | `6` | `6` |

Правила: нужен либо `target`, либо пара `ra`+`dec` (если есть всё, приоритет у `ra`/`dec`).
`ra` и `dec` передаются только вместе.
Форматы осей можно смешивать: например, `ra=133.7951291667` и `dec=-7d14m42.53s`.
Запись RA через двоеточия или с `h` задаётся в часах, Dec — в градусах.
RA 360° (24 часа) нормализуется к 0°. Явная пара задаёт фиксированное направление:
имя, переданное одновременно в `target`, не включает модель движения.

## Формат ошибок

Все эндпоинты возвращают ошибки в одном виде:

```json
{
  "error": {
    "code": "bad_param",
    "message": "dec должен быть в диапазоне -90..90"
  }
}
```

| HTTP | `code` | Когда | Пример |
|---|---|---|---|
| 400 | `bad_param` | неверный или отсутствующий параметр | `mock/error_bad_param.json` |
| 404 | `not_found` | имя не найдено в SIMBAD | `mock/error_not_found.json` |
| 409 | `not_ready` | экспорт GIF до готовности результата | `mock/error_not_ready.json` |
| 502 | `upstream` | IRSA или SIMBAD недоступны после повторов | `mock/error_upstream.json` |
| 500 | `internal` | всё остальное, трейсбек пишется в лог | `mock/error_internal.json` |

## GET /api/resolve

Имя в координаты и собственное движение.

| Параметр | Обязательный | Описание |
|---|---|---|
| `target` | да | имя объекта или `id` пресета |

## GET /api/view

Главный эндпоинт: серия кадров по эпохам. Работает как «получить или запустить»:

1. Если результат есть в кэше, сразу `200` с полным JSON.
2. Если задача уже идёт, `202` с прогрессом.
3. Иначе запускается фоновая задача и приходит `202`.

Фронт опрашивает тот же URL каждые 2 секунды, пока не придёт `200`.
Параметры: см. «Общие параметры». Центр поля считается на сегодняшнюю дату (собственное движение), переменная `CENTER_MJD` закрепляет дату.

### 202: задача идёт

`stage` проходит `query`, `download`, `process`, `render`.

```json
{
  "status": "running",
  "job_id": "ab856bfa",
  "stage": "query",
  "done": 0,
  "total": 0,
  "message": "Поиск снимков"
}
```

```json
{
  "status": "running",
  "job_id": "ab856bfa",
  "stage": "download",
  "done": 1,
  "total": 18,
  "message": "Скачано 1 из 18 снимков"
}
```

Поля ответа:

| Поле | Значение |
|---|---|
| `query` | Фактические параметры; `ra`/`dec` это центр поля (положение объекта на сегодня) |
| `grid` | Общая TAN-сетка всех кадров; `wcs` позволяет перевести клик в RA/Dec |
| `frames` | Эпохи, отсортированы по `mjd`. Эпоха это группа снимков без разрыва больше 30 дней |
| `frames[].n_exp` | Сколько экспозиций вошло в кадр; `wave_um` среднее по их диапазонам длин волн |
| `frames[].image_url`, `flags_url` | PNG кадра и RGBA-маска: красным помечены пиксели, где хотя бы в одной экспозиции установлен флаг качества (значения отдельных битов не расшифровываются) |
| `frames[].predicted_px` | Где объект должен быть на дату кадра (собственное движение и параллакс); `null`, если заданы `ra`/`dec` без имени |
| `frames[].measured_px` | Измеренный центр, если найден ровно один объект; иначе `null` |
| `frames[].measured_candidates` | Найденные центры, см. ниже |
| `frames[].obs_ids` | Идентификаторы наблюдений IRSA |
| `trail_url` | Только в режиме `trail`: одна картинка со всеми эпохами (см. ниже); в остальных режимах `null` |
| `motion` | Пока всегда `null` (не реализовано) |
| `warnings` | Строки с предупреждениями (например, часть снимков не скачалась) |

Все пиксельные координаты (`predicted_px`, `measured_px`, `measured_candidates[].xy`) даны в системе PNG: отсчёт с 0, формат `[x, y]`, ось `y` направлена вниз.

### Центр объекта: `measured_candidates`

Алгоритм не знает заранее размер и тип объекта. Он выбирает два кандидата:
- `largest`: самый большой объект в кадре;
- `central`: объект под центром кадра (если такого нет, ближайший к центру);
- `largest+central`: это один и тот же объект, кандидат один.

### 200: ошибка задачи или пустой результат

- Ошибка в задаче: `200 {"status": "error", "message": "..."}`. Задача после этого удаляется, повторный запрос запускает её заново.
- Снимков нет: `200` с `"frames": []` и предупреждением `"SPHEREx ещё не наблюдал эту область"`. Такой результат не кэшируется, чтобы новые релизы SPHEREx подхватывались.
- Режим `diff` требует минимум 2 эпохи, иначе `frames` пустые и есть предупреждение.

## GET /api/export.gif

Анимированный GIF из уже готовых кадров. Параметры такие же, как у `/api/view`.
Работает только по кэшу: если результата нет, отвечает `409 not_ready` (сначала откройте `/api/view`).

Ответ: `image/gif`. Пример ошибки: `mock/error_not_ready.json`.

## GET /api/sources

Какие локальные таблицы эпох загружены (папка `tables/`, либо `SPHEREX_TABLES`). Если таблица покрывает точку, эпохи берутся из неё (быстро), иначе запрашивается IRSA TAP.
Таблица это экспорт IRSA «Spectral Images» в формате `.tbl`; файлы перечитываются при изменении, перезапуск не нужен.

```json
[
  {
    "file": "spectral-images.tbl",
    "rows": 372,
    "ra": [
      292.32453152743597,
      300.34791431553333
    ],
    "dec": [
      -18.687664822415275,
      -10.772619538696
    ]
  }
]
```

### Режим `trail`

Кадры (`frames`) в этом режиме такие же, как в `diff` (эпоха минус медиана всех эпох). Дополнительно
`trail_url` указывает на одну картинку, где положительные остатки всех эпох **сложены** и окрашены по времени:
самая ранняя эпоха синяя, средние зелёные, самая поздняя жёлтая; прозрачность растёт от 0.55 до 1.0.
Остатки складываются, а не накладываются слоями: при обычном наложении слой с α = 1 стёр бы все предыдущие.
Перед сложением каждая разность делится на свой шум (MAD), поэтому слабые объекты тоже видны.
Фон — приглушённый медианный снимок. Реализация: `src/processing/frames.py::trail`.

## GET /api/spectrum

Спектр в точке «на лету»: фотометрия на всех экспозициях всех 6 детекторов. Работает так же, как `/api/view`:
первый запрос запускает задачу и отвечает `202` с прогрессом, повторять тот же URL, пока не придёт `200`.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `target` или `ra`+`dec` | — | как в `/api/view`. Для `target` апертура следует за объектом (собственное движение) |
| `per_epoch` | `2` | сколько экспозиций брать на эпоху и детектор (`1..10`); больше — точнее, но дольше |

Как считается: вырезка 0.035° вокруг точки, апертура радиусом 2 пикселя на **родных** пикселях экспозиции,
фон — медиана кольца 4–7 пикселей, перевод MJy/sr → μJy через телесный угол пикселя (6.15″)². Длина волны
каждой точки берётся из `WCS-WAVE` в пикселе цели: из-за LVF-фильтра каждая экспозиция видит точку на своей λ.
Реализация: `api/spectrum.py` + `src/processing/photometry.py`.

```json
{
  "status": "ready",
  "query": {"ra": 269.446, "dec": 4.768, "target": "Barnard's Star", "per_epoch": 2},
  "points": [
    {"wave_um": 0.7612, "bw_um": 0.0195, "flux_ujy": 15234.1, "err_ujy": 41.2, "mjd": 60914.21,
     "det": 1, "obs_id": "2025W35_1A_0432_4", "ok": false, "flags": ["OVERFLOW", "SOURCE"]}
  ],
  "n_rejected": 1,
  "warnings": ["1 точек с плохими пикселями в апертуре (часто насыщение яркой звезды): ok=false"],
  "bands_um": {"1": [0.75, 1.09], "2": [1.1, 1.62]},
  "credits": "NASA SPHEREx via NASA/IPAC IRSA"
}
```

- `points` отсортированы по `wave_um`. `ok = false`: в апертуре есть плохие пиксели (насыщение и т.п.),
  поток восстановлен по хорошим пикселям и ненадёжен — показывать серым.
- `flags`: имена флагов в апертуре. `SOURCE` означает только «здесь есть источник», это не ошибка.
- `wavelength`, `flux`, `flux_err`: те же данные плоскими массивами, **только надёжные точки** (`ok = true`) —
  удобно рисовать сразу. В `/api/lightcurve` аналогично: `dates` (`YYYY-MM-DD`), `flux`, `flux_err`.

## GET /api/lightcurve

Поток во времени в **узком** окне длин волн. Считается из точек `/api/spectrum` (тот же кэш, без новых
загрузок); пока спектр считается, отвечает тем же `202`.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `target` или `ra`+`dec`, `per_epoch` | — | как в `/api/spectrum` |
| `det` | `2` | окно = ±5% вокруг середины детектора |
| `wave_min`, `wave_max` | — | явное окно в мкм (передавать вместе, `wave_min < wave_max`) |

Окно узкое специально: с LVF широкое окно смешало бы переменность звезды с формой её спектра.
Обратная сторона: в разные эпохи точка снята на разных λ, и при `per_epoch=1` в окно ±5% часто попадает
одна-две точки (проверено на eps Ind B). Для кривой блеска переменных (RW Aur, R Dra) берите `per_epoch=4..6`.

```json
{
  "status": "ready",
  "wave_window_um": [1.292, 1.428],
  "points": [{"mjd": 60922.07, "flux_ujy": 980.2, "err_ujy": 20.1, "wave_um": 1.35, "det": 2, "ok": true, "flags": []}]
}
```

## Статика

- `/cache/<key>/f<i>.png` и `/cache/<key>/f<i>_flags.png`: картинки из `image_url` и `flags_url`.
- `/` : фронтенд команды (`frontend/index.html`). Понимает параметры в адресной строке: `/?target=barnard&fov=3&det=3&mode=coadd`.
- `/dev/` : тестовая страница API (`static/index.html`).

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `CACHE_DIR` | `cache/` | папка кэша (результаты, вырезки FITS, справочные данные) |
| `PREWARM` | `1` | `0` отключает прогрев пяти пресетов при старте |
| `CENTER_MJD` | сегодня | закрепляет дату пересчёта центра (стабильные ключи кэша для демо) |
| `SPHEREX_TABLES` | `tables/` | папка с локальными таблицами эпох |

## Известные ограничения

- Собственное движение по измеренным центрам (`motion`) не реализовано.
- Холодный спектр качает все 6 детекторов (около 6 × эпохи × `per_epoch` вырезок) — это минуты; кривая блеска потом мгновенна.
- Холодный запрос занимает от десятков секунд до нескольких минут (около 4 МБ и 13 секунд на вырезку); из кэша ответ приходит за миллисекунды.
- Центр объекта определяется по порогу 3 сигма; на очень шумных кадрах порог стоит менять (константы в `api/centroid.py`).
