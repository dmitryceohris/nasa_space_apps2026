Пять целей NASA остаются обязательной проверкой; дополнительно нужны минимум **три реальные звезды вне пресетов**, как предусмотрено твоим новым назначением.

Уже работающие возможности сохраняем, но они не должны задерживать показ изображений или подменять проверку основного сценария. Оформление презентации, видео и повторный сбор готовой таблицы параметров в этот план не входят.

**Твой результат:** изменения по этапам Д1–Д7, тесты, воспроизводимые примеры и запись о том, какие общекомандные зависимости закрыты. Успех твоего кода и готовность всего публичного инструмента фиксируются отдельно: второй результат требует также Б1–Б3.

4. Время кадра брать из `MJD-AVG` и `TIMESYS`, затем `DATE-AVG`; нормализовать в MJD UTC. Если времени FITS нет, использовать доступные метаданные с явным указанием источника. При наличии только нижней границы не называть её точной серединой наблюдения. В текущем библиотечном загрузчике TIMESYS теряется — исправить совместно с обработкой.
5. Предсказание в кадре, отслеживание апертуры в спектральном пути и подписи должны использовать один адаптер модели. Проверить, что вырезка покрывает перенесённое положение на все выбранные даты, включая запас для апертуры/фона.
6. Координаты маркера получать через WCS общей сетки и единственный переворот y при переходе к PNG. Сохранить соглашение API: `[x,y]`, начало с нуля, y вниз. Внекадровый маркер скрывать с предупреждением, а не прижимать к границе.

**Ограничение:** результат готовой модели — геометрическое геоцентрическое направление в осях ICRS. До проверки соглашений WCS и регистрации по опорным звёздам он не становится полной видимой позицией или независимым измерением. Неприменённые поправки и неизвестные ошибки не скрывать.

**Проверки:** исходные эпохи; знаки движения; известные проверки параллакса из `test_sky_motion.py`; сохранённый результат Барнарда; WISE с исходной эпохой MJD; UTC/TAI для одного физического момента; согласие API с готовым предиктором на нескольких датах; одинаковое соглашение координат в `single`, `coadd` и фотометрии.

**Готово, когда:** общая модель действительно вызывается в API для пяти целей, а произвольным звёздам не приписываются недоступные поправки. **Влияние:** Асанали — резолвер и серверные вызовы; обработка — время FITS и сетка; фронтенд — подписи/маркеры. После изменения модели старые результаты кэша должны пересчитаться, включая спектр.

## 5. Общекомандные зависимости: учитывать, но не брать чужую реализацию молча

### Б1. Изображения должны показывать изменение неба, а не артефакты

**Ответственные:** владелец обработки и Асанали; твой вклад — тестовые случаи, проверка времени/координат и смысл метаданных.

- Проверить и интегрировать уже написанный переход на `src/processing`. Плохие нативные пиксели исключаются **до** интерполяции; `SOURCE` не является плохим флагом; отсутствие покрытия отличимо от тёмного неба.
- Вычитать ZODI и остаточный фон. Длины волн брать в нужной точке по спектральному WCS; совпадение детектора или средних длин волн не доказывает одинаковую спектральную выборку. Для сравнения изменения яркости нужны согласованные полосы/отклики; иначе явное ограничение.
- Ограничить длительность эпохи: непрерывный ряд наблюдений не превращать в один многомесячный кадр. Время должно относиться к данным, реально участвовавшим в изображении/измерении.
- Исправить NaN-центроид: примыкающая к краю пустая область сейчас включается в объект и получает максимальные веса. Не заменять проблему принудительным выбором кандидата рядом с прогнозом.
- Для diff разделять положительный/отрицательный остаток или измерять положение по исходному качественному кадру. Центр `abs(new−old)` не является текущим положением звезды. Проверить одну эпоху в `diff` и `trail`: предупреждение не должно приводить к обращению к отсутствующему массиву разностей.
- До вывода значимости в «σ» исправить перенос дисперсии при интерполяции и ковариацию с шаблоном, содержащим тот же кадр. Если это не готово, не представлять такую шкалу как откалиброванную статистическую значимость.

**Критерии:** неподвижная звезда не создаёт сигнал из-за изменения фона; плохой пиксель не становится источником; NaN у края не утягивает центр; две разностные доли не сливаются в ложную позицию; разные полосы не выдаются за надёжную переменность. Тесты нужно запускать через реальный путь `/api/view`, а не только отдельно на библиотеке.

### Б2. Кэш и очередь должны позволять получать актуальные данные

**Ответственный:** Асанали / владелец API. **Твой вклад:** идентичность цели/модели в ключе и сценарии проверки.

- Ограничить срок актуальности списков экспозиций и готовых результатов; пустой поиск обновлять чаще. Изменение версии формата не заменяет обновление данных.
- В ключе различать фиксированные координаты и именованный движущийся объект, версию модели/каталога и параметры выборки. Это касается изображений, спектров и производных кривых блеска. Старый прогноз не должен приходить в координатный запрос из-за совпавшего центра.
- Частично загруженные наборы должны повторять пропущенные экспозиции/эпохи. Локальная таблица не должна скрывать более новые данные без явно включённого режима ограниченной выборки.
- Устранить гонку cache miss → завершение другой задачи → удаление Job → повторный запуск. Проверять завершённый результат и состояние задачи согласованно.
- Ограничить очередь, время работы и срок хранения забытых задач; различать ожидающий запрос и зависшую работу. Не ограничиваться числом исполняющих потоков.

**Критерии:** новый релиз или восстановление IRSA видны без ручного удаления кэша; два одинаковых запроса используют одну задачу; при перегрузке возвращается понятный временный отказ; модель из Д3 не использует старые картинки/спектры по несовместимому ключу.

### Б3. Доступный извне рабочий инструмент

**Ответственный:** владелец публикации вместе с API/фронтендом. **Твой вклад:** финальные сценарии Д6 и проверка с другого устройства.

- Подготовить воспроизводимые зависимости и запуск. Локальный `start.sh` по умолчанию слушает loopback: для публичного доступа нужен явно настроенный доступ извне, домен/адрес и соответствующий способ размещения.
- Настроить постоянный кэш, ограничения нагрузки и обработку отказов сервисов; сайт не должен зависеть от содержимого личной папки разработчика.
- Проверить главную страницу и API по одному публичному адресу, получение PNG, координатные ссылки, холодный запрос, повторный запрос и ошибки. `/dev/` не заменяет основной пользовательский сценарий; маршруты `/dev` и `/dev/` проверить отдельно, если они остаются доступны.
- Наличие только исходников, доступ по localhost или mock-анимация не закрывают требование objective о публичном инструменте.

**Критерий:** внешняя ссылка открывает реальные кадры и позволяет воспроизвести обязательный сценарий с другого устройства. Дилайла не отмечает весь objective выполненным только по окончании своих этапов.

## 7. Проверки и команды

Из корня проекта; `uv sync --locked` нужен для установки окружения, если его ещё нет. В обычном тестовом прогоне сеть отключена по смыслу фикстур, но не заменяется утверждением, что живой архив проверен.

```sh
uv run --offline --locked pytest -q
uv run --offline --locked pytest -q tests/test_api.py tests/test_api_trail_spectrum.py tests/test_centroid.py
uv run --offline --locked pytest -q tests/test_barnard_motion.py tests/test_sky_motion.py
```

Для просмотра основной страницы локально, без автоматической загрузки пяти целей на старте:

```sh
PREWARM=0 uv run --offline --locked uvicorn api.main:app --host 127.0.0.1 --port 8000
```

Открыть `http://127.0.0.1:8000/`. Это локальная проверка, не публичный адрес. Живую загрузку включать отдельно, ограниченным сценарием:

```sh
SPHEREX_LIVE=1 uv run --offline --locked pytest -q tests/test_exposure.py::test_live_barnard_cutout
```

Здесь `--offline` относится к разрешению зависимостей uv; сама живая проверка обращается в архив. Для проверки уже готового расчёта без сети и без перезаписи исходного результата:

```sh
uv run --offline --locked python sky_motion.py --observations data/physics_observations.csv --output /tmp/spherex-dilayla-predictions.csv
```

**Новые проверки по плану** добавить в существующие файлы либо в новые `tests/test_resolve.py` и `tests/test_target_workflow.py`: эти два файла пока не существуют. Браузерные сценарии должны проверять основную страницу, а не ограничиваться `TestClient`, который не исполняет JavaScript.
